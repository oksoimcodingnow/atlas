The Study
Flow.

A ritual for turning curiosity into competence. Six moves you cycle every day. Nothing fancy — just a loop that runs.

01
Capture

Write the question down.

Before you open anything, write the question you're trying to answer on one line. Make it falsifiable. "How does Brinson attribution decompose returns?" beats "learn attribution."

Drop the question into a Schedule task tagged study. If you're not sure where it fits, it lives in Inbox until you do.

Schedule
02
Source

Pick the primary source.

Open the relevant NotebookLM notebook (e.g., Quant Finance). If the right textbook or paper isn't in there yet, upload it now. One notebook per domain — not per topic. Domains last; topics rotate.

For commute or chores: trigger an Audio Overview on the notebook and listen. Passive intake is the priming.

NotebookLMAudio Overview
03
Ask

Bring the question to Claude.

Open Claude. Quote the source passage. Ask in plain language. If it's quant or risk, Claude's finance skills will fire automatically (Sharpe, VaR, GARCH, Kelly, attribution — all installed). Ask for the worked example, not just the formula.

Push back. "Why that denominator?" "What happens when the assumption breaks?" The answer you accept too fast is the one you'll forget by Friday.

Claudefinance skills
04
Code

Implement once.

Open the quant repo. Write the concept as code — a function in alphas/, a notebook cell, a one-off script. Run it on real BTC bars from utils.data_loader. If the number you get matches the worked example, you've actually learned it. If not, go back to step 3.

Don't optimize. Don't generalize. One concrete instance. The generalization comes from cycling the loop, not from one pass.

05
Log

Close the loop in writing.

Tick the Schedule task. Add a one-paragraph note in quant/research/ — what you asked, what stuck, what you'd ask next. Future-you is the audience.

If the topic is now solid: archive the question. If it broke open new questions, add them to Inbox. Done is a checkbox and a sentence.

Schedulequant/research/
06
Cycle

Trust the repetition.

One full cycle in 45 minutes is plenty. Three in a day is a great day. Don't chase the eight-hour deep-work fantasy — the loop is what compounds, not the heroic session.

Weekly: skim quant/research/, retire dead questions, promote two open ones into This Week on Schedule. Monthly: snapshot what's now reflexive vs still hand-wavy.

Cadence

When you do what.

Daily · 45 min

One full loop

Steps 01 → 05. Pick one question. Source it, ask it, code it, log it. Three cycles ≈ a great day.

Weekly · Sunday

Triage

Read quant/research/ notes from the week. Retire what's done, promote two open ones, add new from the wild.

Monthly · 1st

Snapshot

List what's reflexive (you can derive it without notes) vs still hand-wavy. The wavy list is next month's curriculum.

Always

Falsifiability

Every question is testable. Every answer cites a source. Every implementation is one concrete instance. No hand-waving allowed in the log.

Coda

The flow is the work.

You don't need a longer attention span. You need a shorter loop — and the discipline to run it tomorrow.
