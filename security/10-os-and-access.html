Lesson 10 · Systems & scale

Who's allowed to do what.

Every operating system is, underneath, a referee deciding which users may touch which files and run which commands. Attackers rarely get full control on the first move — they get a toehold, then climb. Understanding that climb is understanding how breaches actually deepen.

~8 min · interactive · builds on Lessons 2 & 9

When an attacker "gets in," they usually land as some limited user — a low-privilege account, a web-server process. The real damage comes from privilege escalation: climbing from that toehold to full control. The defender's job is to make that climb as hard as possible.

The access-control vocabulary — defined

users, groups & permissions
The OS tags every file and action with who may read, write, or execute it. You belong to groups; permissions are granted to users and groups. This is access control at the machine level.
privileged vs unprivileged
A normal user can only touch their own stuff. A privileged account (root on Linux, Administrator on Windows) can touch everything — install software, read any file, change the system. The crown.
principle of least privilege
The recurring hero of this course: give every user and process the minimum rights it needs. Don't run as admin for daily work; don't let the web server read the password file. Less privilege = smaller blast radius.
privilege escalation
An attacker turning limited access into full control. Vertical = low user → admin. Horizontal = one user → another user's data. Usually via an unpatched bug, a weak permission, or a stolen credential.
sandboxing & isolation
Running code in a confined box (a container, a VM, a browser tab) so even if it's malicious, it can't reach the rest of the system. The structural form of least privilege.

Watch an attacker climb

An attacker landed as a low-privilege web user. Toggle your hardening on, then let them try to escalate to root and reach the sensitive data. See how each defense cuts off a rung of the ladder.

Your system hardening

Attackers don't usually break the front door wide open. They slip a foot in, then climb. Take away the rungs and the toehold stays a toehold.

The practical hardening

Don't work as admin. Use a normal account daily; elevate only when needed. Patch the OS. Most escalation exploits target known, already-fixed kernel/service bugs. Least privilege for services. The web server, the database — each runs as its own limited account that can't touch the rest. Sandbox untrusted code. Containers/VMs so a compromise stays contained (this is exactly why you'd run Blender MCP or any "run my code" tool in a VM).

Recap

An OS is an access-control referee: users, groups, and permissions decide who may do what. Attackers land low and attempt privilege escalation to reach the crown. The defenses are this course's refrain made concrete: least privilege (small blast radius), patching (close the escalation bugs), and sandboxing (contain the compromise). Make the climb hard, and a toehold never becomes a takeover.
