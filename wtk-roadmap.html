4 · What to optimize (and when)

Honest priorities. Don’t optimize what you haven’t built. Fidelity & finishing beat polish early.

High · now

Card data accuracy

Every card’s suit / number / count / text must be exact. The whole game reads from this — a wrong card here is a bug everywhere later. Slowest to fix later, cheapest to get right now.

High · now

Finish transcribing ALL cards

Resist building game features before the deck is complete. A half-deck means a half-game. Breadth first, depth later.

Medium · soon

Secret-info privacy

The MVP is “soft-hidden” (trust + pass the device). The real fix is Cloud Functions so a clever friend can’t peek via the console. Worth it only once you’re online & want it cheat-proof.

Medium · later

Generals & special powers

The depth layer — each hero’s unique skill. Big content + logic work. Adds the “real WTK” feel, but only after the core loop runs online.

Low · later

Visual polish & animation

Card art, motion, sounds. Delightful, but zero gameplay value until it plays. The classic trap: polishing a thing that doesn’t work yet.

Low · later

Performance / scale

Firestore read counts, image sizes. Only matters at real usage. For you + friends it’s a rounding error — don’t pre-optimize.
